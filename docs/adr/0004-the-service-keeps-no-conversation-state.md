# The Nemu Service keeps no conversation state; the extension carries Guide progress

Every `runNemu` call derives its calculations, citations, actions and Guide from the current validated request and the injected runtime data. The Service stores no conversation plan and never reuses an earlier response. The Nemu Extension persists the Guide id and progress across page navigation: after an allowed navigation click, or when the URL changes while a Guide is active, it waits for stable elements and asks the same prompt again with the fresh Element List, once per distinct page and step state. The Service recalculates `current_step` from that request. We did not add a server-side session store: it would break the Worker-friendly request lifecycle, let a stale DOM target outlive its page, and let one answer leak into the next (a refusal after a Makassar answer must carry no calculations, actions, citations or Guide). A Guide lists targets that may be on future pages, so only the steps that match the current Element List become executable actions.
