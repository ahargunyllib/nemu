# A second Knowledge Workspace reuses the same seams instead of a generic workflow engine

Klaim SLA (`W-TELKO`) runs beside Perjalanan Dinas (`W-TRAVEL`) on the same request, response, `fill`, Guide, citation and Action Level contracts. What differs is a workspace discriminator on the process context, its deterministic tools and canonical Guide steps, and the knowledge and rows selected for it. Each request loads its runtime data (profile, process context, reference tables, active knowledge chunks, required documents) through the injected `NemuRuntimeDataSource`, and a missing table or profile field fails clearly instead of falling back to the bundled demo data. We did not build a BPMN runtime, workflow DSL, vector database, paid retrieval provider or full multitenancy: two concrete workflows have not yet shown what the stable abstraction is, and a provider is wired in only once the user chooses it. The cost is that a third workspace needs its own deterministic code until that abstraction is clear. Uploaded Markdown is indexed immediately; a PDF stays a downloadable attachment but fails indexing with an explicit "not configured" status. The evaluator-only answer-key package is never indexed.
