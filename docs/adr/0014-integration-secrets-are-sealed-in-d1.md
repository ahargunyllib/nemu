# Integration secrets are sealed in D1 with a Worker key

Nemu reads a school's AlurSekolah (and later Moodle) with keys the school hands Javan, and a teacher's extension must never hold them. Admin Javan enters them in WS-07, and the Nemu Service seals each value with AES-GCM (WebCrypto) before it goes into D1 (`integration_secret`). The AES key is SHA-256 of the Worker secret `INTEGRATION_SECRETS_KEY`, and each ciphertext is bound to its workspace and setting name, so a copied row doesn't decrypt elsewhere. Only the last four characters are stored in the clear, which is all the Admin Workspace ever gets back: no procedure returns a stored value, and "Ganti" replaces it. We chose this over one Worker secret per school because schools are added at runtime, and over Cloudflare Secrets Store because the MVP doesn't need its rotation features. Rotating `INTEGRATION_SECRETS_KEY` makes every stored value unreadable; the values are then entered again in WS-07. The AlurSekolah base URL is stored the same way, so the same adapter reads the mock or a school's real tenant, and the real tenant's address stays out of this public repository.
