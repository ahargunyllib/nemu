# Deterministic code owns business facts; the model only phrases

Monetary values, deadlines, missing documents, workflow and Guide order, SLA interval merging, rounding and approval routing come from deterministic code and stored data, never from model output. The model words the answer from those trusted facts and picks supporting evidence; it does not do arithmetic or infer a formula or approval policy. A `fill` action therefore carries a raw value only when it comes from a successful deterministic calculation (Momen 2 fills the lodging result `447000`, not the SBM rate `745000`), only at Action Level `konfirmasi`, only for a target in the current Element List, and never when the safety classifier failed, detected injection, or returned `dilarang`. A claim whose RCA is not approved returns `PERLU_BUKTI` and no final amount. Deterministic tool results carry the source ids they used; these merge with the model's evidence ids and must resolve to active knowledge, otherwise the pipeline errors instead of showing an ungrounded source. Inactive knowledge is never retrieved.
