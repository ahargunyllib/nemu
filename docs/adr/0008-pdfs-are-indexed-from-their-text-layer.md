# PDFs are indexed from their text layer

An uploaded PDF is indexed like Markdown: `unpdf` reads each page's text layer inside the Worker, the pages are joined with the same `[Halaman N]` markers the knowledge sources use, and the Markdown chunker splits them, so chunks keep their page, Pasal and ayat. A numbered point ("3.2 …") is a chunk of its own: its article, or a decimal ayat inside a Pasal ("3 ayat 3.2"). A header or footer line repeated at the top or bottom of most pages is dropped, so it never lands in a point. This replaces the "PDF indexing is not supported" failure from ADR-0006. A PDF with no text layer (a scan) fails with a message that OCR is not supported; OCR would need a paid provider, which is wired in only once the user chooses one. Extraction runs inside the upload request, so a very large PDF can exceed the Worker's CPU limit; moving indexing to a queue is the next step if that happens.
