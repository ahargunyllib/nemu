# Sumber opens a cited document through a short-lived signed link

Sumber on an answer opens the cited PDF at its page (#258, PRD "PDF dibuka di halamannya"). The Nemu Extension proves who the teacher is with headers, not a session (ADR-0015), and a tab opened on a link sends none. So the extension first calls `documentFileLink`, a `schoolProcedure` that checks the caller's school reads the document (active and ready, the school's own or a package for all schools: what Nemu answers from) and that it is a PDF. It returns a path on the Nemu Service, `/api-reference/documents/<id>/file?token=…`, valid for 10 minutes. The token is the school, the document and the expiry, signed with HMAC-SHA256 under a key derived from `BETTER_AUTH_SECRET` with its own purpose label, so no new secret is needed. The background opens it with `#page=<page>` in a new tab next to the teacher's, and the file route serves it `application/pdf`, inline, after checking the signature, the expiry and that the school still reads the document (switching it off in WS-04 closes links already handed out).

We considered a Better Auth session for the tab (teachers have no Nemu login, by ADR-0015), the extension fetching the PDF and opening a `blob:` URL (the blob dies with the page that made it, and `#page=` on blob URLs depends on the viewer), and signing links into every `helpAsk` answer (links would outlive the bubble and be minted for sources nobody opens). Anyone holding a link can open that one document until it expires; that is no more than the teacher could forward as a file.
