# BPMN symptoms are indexed on upload and traced in code

"Nilai Aisyah kok tidak muncul di aplikasi orang tua?" (F2-08) has to be answered from whatever BPMN the school uploads, not from a flow Nemu knows by name (F3-11 to F3-14). So the work is split by when it happens. On upload, one model call (`suggestSymptoms`) indexes each task, end event and triggering event by its element ID: the symptoms a teacher or parent sees there, the step that undoes it (its way back) and the school role who can help. WS-04 stores that index per element, and the operator corrects it there. Offline, the symptoms are the element documentation's own sentences that say something is missing or blocked.

On a question, the teacher's words are matched to the index in code first: a symptom sharing enough content words is the match, a question sharing fewer than two words with every symptom is not a process question, and only a near miss goes to the model, which can only pick one of the indexed symptoms by number. From the matched element, code walks the graph (`traceCause`, ADR-0010): back to the event that set it off, forward to the nearest end event, and over to the way back. The lane of a step on that walk, or the role the index gives, picks the contact from the workspace. The model then only puts the walk, the steps and a reply for the parent into plain words. Step order, the contact, the citation and the guardrails stay in code: no amount and never "tunggakan" in the parent reply, no secrets, and a failed or cut-off phrasing falls back to the code's own drafts.

We index on upload because the question path has to stay within the voice budget (≤ 4 s) and the operator should see what Nemu will say before a teacher asks. We trace in code because the answer may only name steps that are in the school's own file.

We accept three consequences. A cause Nemu can't check is never said as a fact: when the question names a student whose grades AlurSekolah shows as saved, or can't be asked about, the answer opens "Kemungkinan karena alur …", since the SPP bill is outside the API key's scope (PRD D4, #266). A symptom no process covers is "Belum ada di proses sekolah" (F3-14), not a guess. And an index the model got wrong stays wrong until the operator corrects it in WS-04.
