# Admins choose the source each deterministic rule cites

A deterministic rule (an SBM lookup, the 30% lodging lump sum, the accountability deadline, a Klaim SLA cutoff, formula or approval route) cites a Rule Source: a document plus an article/section and/or page in that Knowledge Workspace. Each rule has a key and a default location in `RULE_SOURCES` (`packages/ai/src/sources.ts`) that points at the seeded document; an admin can re-point it at any document in the workspace from the Admin Workspace Documents page, and reset it to the default. The `rule_source` table stores only those overrides and is cleared when its document is deleted. Every request resolves each rule to an active chunk before calling `runNemu`; a rule whose location matches no active chunk is absent, so only the calculation that needs it returns the safe error (ADR-0005) and the admin page reports it as "Not found". Locations are matched by document, article and page rather than chunk id, so re-indexing a document keeps its citations. We chose this over matching documents by title or a stable code because a new regulation version can renumber pages and articles: only a person can say where the new rule lives. The rules themselves stay in code: a new rule still needs a code change and a default.
